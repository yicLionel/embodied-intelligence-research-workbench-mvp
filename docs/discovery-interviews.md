# Discovery Interviews: FA Industry-Research Workflow

## Status and evidence boundary

**Status: two interviews recorded; go/no-go gate met.** This document contains the approved, privacy-preserving interview protocol and two anonymized sessions. The two-session evidence permits the confirmed MVP scope to proceed under the specified gate, but it is a small-sample baseline and does not establish step-level time ranges.

This is deliberately a pre-build evidence record. It is based on two real conversations with boutique-FA interns or analysts whose industry-research task was completed within the previous 90 days. It does not replace later Task 10 user testing or establish performance outcomes.

### Privacy rules

- Assign a sequential session code (`DV-01`, `DV-02`, then `DV-03` if needed).
- Do not record a person’s name, employer, client, deal, project, contact detail, confidential document, or verbatim sensitive information.
- Capture role level only as `intern` or `junior analyst`; record research-work recency as a rounded range.
- Record time only as participant-reported ranges, never as measured facts unless a later user test measures it.
- Store paraphrased workflow evidence and non-sensitive examples only.

## Session protocol

Use the questions below in the same order for every participant. First reconstruct the participant’s existing workflow. Do not describe or pitch the proposed product until question 9.

1. Think of the most recent industry-research task you completed in the last 90 days. What was its purpose and deadline? Please omit confidential context.
2. Starting from receipt of the task, what did you do next? Walk through each step in order and name the tools used.
3. For each step, what was your participant-reported time range? Include scoping, searching, extraction or note taking, reconciling conflicting information, citation cleanup, and writing.
4. Which actions involved repeating searches, copying information between tools, or reformatting material? What made them repetitive?
5. Describe any source or citation failure you encountered: inaccessible material, an unsupported conclusion, mismatched source content, an out-of-date source, or conflicting figures. How did you discover and resolve it?
6. Who reviewed the work, if anyone? What corrections were requested and how were they made?
7. What confidentiality or process constraints shaped the way you researched, stored evidence, or shared a draft?
8. Which part of the workflow was most difficult or risky? Why?
9. Now consider a workflow that moves from a confirmed research framework, to traceable evidence, to a brief generated only from reviewed evidence. What part would help, and what concerns would you have?
10. Would you accept this evidence-review checkpoint: the system may create a clearly labeled, non-exportable preview from accessible candidate evidence with directly supporting quotes; the preview shows citations and pending/unconfirmed status; the user reviews high-risk evidence and key data; and only user-confirmed evidence can enter a formal/exportable brief? Why or why not?
11. What single condition would stop you from using such a workflow?

### Design implications and product changes

The clarified product implication is: the system may create a clearly labeled, non-exportable preview from accessible candidate evidence with directly supporting quotes, while keeping citations and pending/unconfirmed status visible. Review is risk-prioritized before **formal export**, not an expectation that the user must reopen every source before any draft exists. The user may continue source review from the cited preview. Every fact included in a formal export still requires a user confirmation state; clean records may be explicitly batch-confirmed. Unsupported or inaccessible evidence cannot enter either preview or formal output.

The clarified interaction requires aligned signed-off design and implementation-plan updates: they now distinguish the bounded candidate preview from confirmed-evidence-only formal export. The core evidence-first commitments remain unchanged—risk flags and human review are prioritized, confirmation states are preserved, and formal output remains restricted to confirmed evidence.

## Go/no-go decision record

**Decision: go — proceed unchanged with the confirmed MVP scope.**

The gate is met with `n=2`: both `DV-01` and `DV-02` reported material repetitive or reconciliation work and accepted the clarified evidence-review checkpoint. That checkpoint permits a clearly labeled, non-exportable preview built only from accessible candidate evidence with directly supporting quotes and visible citations/pending status; it then requires human review of high-risk evidence and key data before formal export, which contains only user-confirmed evidence. It does not require manual reopening of every source before a draft exists.

The gate permits proceeding unchanged only when at least two participants both:

1. report material repetitive search, extraction, or citation work; and
2. accept an evidence-review checkpoint.

If the completed interviews do not meet both conditions, revise the target workflow in the signed-off design specification and implementation plan before product code is written. If they do meet the conditions, update this document with raw session counts, the evidence summary, and the resulting decision before code begins.
