# 在线行业调研工作流规格

## 目标

用户在首页选择行业、地域、时间范围和研究用途后，系统自动生成固定七维研究框架。只有框架中的问题全部批准，系统才允许启动网络检索；检索结果进入本地 SQLite 的来源表和待审核证据表，人工确认后才可进入正式简报。

## 端到端流程

1. 创建在线研究项目，生成稳定的 `online-*` 项目 ID 和七条未批准问题。
2. 在“研究框架”页编辑、保存并批准问题；未全部批准时，资料来源页的检索按钮保持禁用。
3. 以每个维度生成三条中英文查询，调用 Tavily 公开网页搜索，并按规范化 URL 去重。
4. 保存来源标题、组织、角色、日期、URL 和访问状态；搜索摘录先作为 `pending` 候选证据。
5. 若配置 `DIFY_EVIDENCE_API_KEY`，把问题和来源交给 Dify Workflow 做证据结构化；失败时保留 Tavily 摘录，不丢失已完成结果。
6. 证据矩阵沿用可访问性、直接引文、引用和风险护栏；只有 `confirmed` 事实可进入正式简报。
7. 若配置 `DIFY_BRIEF_API_KEY`，将已确认事实交给 Dify Workflow 生成专业风格 Markdown；否则使用本地确定性简报生成器。

## 配置

- `TAVILY_API_KEY`：必需，负责实时公开网页检索。
- `DIFY_EVIDENCE_API_KEY`：可选，负责把检索结果整理成候选证据。
- `DIFY_BRIEF_API_KEY`：可选，负责正式简报语言润色和结构化。
- `DIFY_BASE_URL`：默认为 `https://api.dify.ai/v1`。
- `ONLINE_RESEARCH_TIMEOUT`：单次 provider 请求超时，默认为 60 秒。

没有配置密钥时，离线演示项目仍可完整运行；在线项目会明确显示缺少的必需配置，不会假装完成实时检索。

## 失败与恢复

- Provider 请求遇到限流或 5xx 时自动重试一次。
- 单个维度失败不会删除其他维度已保存的来源和证据，结果页显示部分失败摘要。
- Dify 结构化失败时降级到带原文摘录的 `pending` 证据，继续由人工审核。
- 证据引用不完整、来源不可访问或缺少直接引文时，确认按钮保持阻断。

## 验收标准

- 在线项目固定生成七个维度且顺序稳定。
- 相同 URL 的跟踪参数、片段和尾部斜杠不会产生重复来源。
- 没有 Tavily 密钥时检索按钮不可用，并说明如何配置。
- 模拟检索可持久化去重来源，并为每个维度生成待审核证据。
- 18 个自动化测试与 Ruff 检查全部通过。
