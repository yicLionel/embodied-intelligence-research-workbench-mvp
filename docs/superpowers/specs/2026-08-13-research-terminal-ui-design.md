# 研究终端界面升级设计规格

## 目标

将现有离线工作台升级为适合精品投行/行业研究展示的深色研究终端，同时保留五页架构、SQLite 数据模型和所有证据审核门禁。

## 视觉系统

- 使用深海军蓝作为应用背景，暖白/浅灰作为内容面板，低饱和金色用于主操作、当前阶段和重点指标。
- 标题采用紧凑的研究终端风格，正文优先保证数据密度与中文可读性。
- 风险、审核状态和简报模式始终同时显示文字及颜色；色彩不可成为唯一状态载体。
- 全局在顶部保留项目名称、范围、离线模式、当前阶段和审核统计。侧栏显示品牌、五阶段进度与演示数据入口。

## 信息架构

五页保持不变；进入任一有项目的页面时都显示统一的项目状态带：已确认、待审核、待修改、高风险及审核进度。

1. **研究需求**：改为项目控制台。显示研究范围、核心任务、七维覆盖进度、风险概览与明确的下一步卡片；无项目时提供有价值的空状态与装载演示入口。
2. **研究框架**：以阶段标题、审核计数和维度卡片呈现问题；保留编辑、批准、保存与确认门禁，确认资格及阻塞原因显式可见。
3. **资料来源**：以可筛选、紧凑的来源表呈现机构、角色、日期、可访问性与提取状态；保留来源剔除的连带影响提示。
4. **证据矩阵**：新增状态/风险筛选、审核 KPI 和风险分布概览；默认按既有风险优先级排序。每条证据在展开详情中显示原文、来源、元数据、风险和审核操作。
5. **研究简报**：并列展示候选预览和正式简报的资格、计数、限制和操作。预览保持不可导出；正式输出仍仅在已确认且逐句映射验证通过时显示导出控件。

## 数据与交互

所有新增 KPI、进度、图表和表格只从现有 repository 的项目、来源和证据记录计算，不引入外部请求或新持久化字段。筛选只改变当前页面视图，不改变证据状态。来源剔除、审核状态切换、框架保存与简报导出规则保持原有事务和守卫逻辑。

演示数据首次装载后，首页应能显示：七维问题覆盖、证据总数、已确认/待审核/待修改数量、高风险数量、来源可访问率和风险分布。无合格正式证据时，正式简报区必须说明缺少什么、当前已保留什么以及下一步审核动作。

## 验证

保留并扩展 AppTest：验证工作台标题、状态带、五页标题、未装载项目空状态、演示项目 KPI、证据筛选和正式简报阻断。单元测试继续覆盖审核护栏、预览/正式证据筛选、SQLite 事务与导出。

手工视觉检查以 1440px 宽桌面视图完成，确认导航、顶部状态带、KPI、表格和风险文字可见，且没有横向溢出或仅颜色表达状态。运行全量 `pytest`、`ruff check` 和 Streamlit 启动 smoke test 作为发布门槛。
