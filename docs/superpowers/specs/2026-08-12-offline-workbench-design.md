# 离线可演示研究工作台设计规格

## 目标

交付一个可在本地运行、可重复演示的具身智能行业研究工作台。它实现产品的五阶段流程、本地 SQLite 持久化及证据审核护栏，不调用 Dify、Tavily 或 OpenAI；未来在线工作流通过清晰的服务边界接入。

## 范围与非范围

范围包括中文 Streamlit 五页工作台、单项目持久化、固定七维研究框架、内置演示来源和证据、确定性质检、人工审核、候选预览、正式简报、Markdown/CSV 导出及自动化测试。

本阶段不包括账号、多人协作、真实网络搜索、上传文件解析、Dify/Tavily/OpenAI 密钥、实时费用确认、云部署或真实用户测试。界面显示离线演示模式，不能暗示数据为实时研究结果。

## 架构

`streamlit_app.py` 提供固定左侧导航和当前项目选择。页面模块只负责渲染与调用应用服务；领域模型、SQLite repository、演示数据装载器、质量规则、简报验证和导出逻辑位于 `src/`，以便脱离 UI 单独测试。

SQLite 是唯一持久层：使用 WAL、外键与显式事务。库保存项目、问题、来源、证据、审核事件、简报和 checkpoint；应用重启后根据同一数据库路径恢复完整项目。所有演示数据为仓库内的匿名合成资料，不保存原始上传内容、密钥或供应商 payload。

## 五页与数据流

1. **研究需求**：创建或编辑项目的 `topic`、`geography`、`time_range`、`purpose` 与 `focus_questions`；默认值为具身智能、中国为主全球对照。页面说明离线演示模式并提供“装载演示研究”动作。
2. **研究框架**：固定显示七个且仅七个维度；每维演示问题初始未批准。用户可编辑问题文字和 1–3 优先级、删除问题，并逐条批准。每维至少保留一条且全部保留问题均获批准，才可进入资料来源。
3. **资料来源**：展示演示来源的标题、机构、角色、发布日期、URL/reference、访问与提取状态。剔除来源必须原子地把关联证据设为 `discarded`，并保留审核事件。
4. **证据矩阵**：展示一事实一记录的 claim、引用、地域、时期、单位、定义口径、风险及审核状态。排序优先级固定为 blocked、conflict、stale、incomplete、needs_edit、pending、confirmed、discarded。没有可访问来源、非空直接引文或 URL/reference 的记录不能确认；允许 `pending`、`needs_edit`、`confirmed` 和 `discarded` 状态转换并记录原因/时间。
5. **研究简报**：候选预览仅使用可访问、有非空引文、有 URL/reference、非 discarded 且状态为 `pending`、`needs_edit` 或 `confirmed` 的证据；页面以文字标记“待审核、不可导出”，逐条显示实际审核状态、引用与风险，且没有导出控件。正式简报只使用 `confirmed` 证据；每一句事实性陈述必须映射到一条 confirmed 证据，验证失败时阻断输出。验证通过后允许复制 Markdown 和导出证据 CSV。

## 质量与恢复规则

市场数值的 geography、period、unit、definition_scope 任一为空即 `incomplete`。不同 definition_scope 或同口径不同数值产生 `conflict`；融资、商业化、竞争相关来源超过 12 个月标记 `possibly_stale`，市场/供应链来源超过 24 个月标记，技术原理与标准不按时间自动淘汰。风险和模式必须用可见文字呈现，不能仅靠颜色。

演示数据必须覆盖：可确认的干净记录、定义冲突、可能过旧、字段缺失与不可访问来源。每次会改变一组持久化对象的操作使用事务；失败时保留上一次有效结果并显示发生内容、保留内容和下一步动作。checkpoint 保存 sanitized status、completed unit IDs、错误摘要和 UTC 更新时间。

## 测试与验收

单元测试覆盖领域状态、SQLite 重启恢复与 rollback、风险排序与标记、审核门禁、预览/正式证据选择、句子映射以及 CSV/Markdown 导出。Streamlit AppTest 覆盖五页可见性、框架门禁、不可确认记录与简报验证阻断。`pytest`、`ruff check` 和本地 Streamlit smoke test 是交付门槛。

## 后续在线接入

将来增加 Dify 时，在线适配器只负责生成框架、收集来源/证据及生成候选文本，并输出既定领域模型。SQLite 护栏、审核状态、候选/正式筛选和简报句子映射始终保留在本地应用层，不由供应商工作流绕过。
