# 具身智能行业研究工作台：MVP 产品设计规格

- 日期：2026-08-10
- 状态：设计已确认，可进入实施
- 目标周期：2–3 周，接近全职投入
- 产品类型：求职作品集为主、真实用户验证为辅的 B-lite MVP

## 1. 产品摘要

本产品面向精品 FA 的实习生和初级分析师，将公开网络搜索与用户补充的不超过 5 项文件或链接，转化为可追溯、可审核的证据矩阵，并在人工确认后生成结构化行业研究简报。

首发场景限定为具身智能行业研究：中国市场的商业化、融资和产业链为主，全球技术趋势与标杆公司作为对照。产品不尝试替代投资判断，也不承诺全自动完成研究；它自动化重复的信息搜集、提取和整理工作，把范围确认、口径判断和事实审核保留给人。

## 2. 背景与问题

精品 FA 的行业研究通常重复经历以下过程：确定研究范围、拆解问题、搜索资料、核对数据口径、整理引用、撰写简报。重复劳动主要集中在搜索、摘录、字段整理和格式转换；高价值判断主要集中在市场定义、来源可信度、冲突解释和商业含义。

现有通用 AI 搜索或聊天工具存在四个核心缺口：

1. 输出直接进入长文本，缺少可审核的中间证据层。
2. 市场规模、CAGR、地域、年份和统计口径容易混用。
3. 引用可能不可访问、与结论不匹配或已经过时。
4. 用户难以定位需要人工判断的异常，只能逐句复查。

## 3. 目标用户与核心任务

### 3.1 第一目标用户

精品 FA 的实习生和初级分析师。

### 3.2 核心使用场景

用户需要在有限时间内对一个陌生或快速变化的赛道形成基础行业认知，并为内部讨论、项目筛选或客户材料准备一份有来源的研究底稿。

### 3.3 Job to Be Done

当我需要快速研究具身智能行业时，我希望系统帮助我建立研究框架、搜集和整理可靠证据、暴露口径冲突，并基于我确认的事实生成简报，从而减少机械整理时间，同时保留我对范围、事实和结论的控制。

## 4. 产品目标与非目标

### 4.1 产品目标

1. 将行业研究从一次性聊天转化为分阶段、可追溯的工作流。
2. 让每条关键结论能够回到原始证据、来源日期和统计口径。
3. 自动识别来源过旧、数字冲突、定义混用和证据缺失。
4. 在 3–5 名真实目标用户中验证任务完成、时间改善和复用意愿。
5. 形成可用于求职展示的用户研究、PRD、原型、评测集和迭代证据。

### 4.2 首版非目标

1. 不建设完整账号、支付、权限和多人协作系统。
2. 不支持多个行业的通用研究模板。
3. 不自动生成精美 PPT 或复杂 Word 排版。
4. 不建设大规模私有知识库或长期监控系统。
5. 不自动完成投资判断、公司推荐或对外联系。
6. 不宣称流程无人审核或结果可以直接用于投资决策。

## 5. 研究边界

### 5.1 地域边界

- 中国：商业化进展、融资活动、产业链和主要参与者。
- 全球：技术趋势、关键研究方向和标杆公司对照。
- 任何市场规模或增长率必须明确标注地域，禁止将中国与全球数据混为同一序列。

### 5.2 具身智能口径

产品必须区分“具身智能”“人形机器人”“工业机器人”等概念。来源采用不同定义时，系统并列保留原定义并生成口径冲突提示，不擅自归并为同一市场。

### 5.3 首版研究维度

1. 市场定义与边界；
2. 市场规模与 CAGR；
3. 产业链与关键环节；
4. 竞争格局与标杆公司；
5. 技术趋势与能力演进；
6. 融资活动与商业化进展；
7. 风险、争议与关键假设。

## 6. 核心用户流程

1. **定义研究任务**：用户输入主题、地域、时间范围、研究用途和重点问题，并可补充不超过 5 项文件或网页链接。
2. **生成研究框架**：系统根据固定行业模板生成问题树和搜索计划。
3. **人工确认框架**：用户增加、删除或修改研究问题；未确认前不进入大规模搜索。
4. **搜索与读取**：系统搜索公开网页并读取用户补充材料，保存来源元数据。
5. **结构化提取**：系统从原文提取结论、数值、地域、年份、单位、统计口径和直接证据。
6. **质量检查**：系统识别来源过旧、定义混用、数字冲突、引用缺失和低可信来源。
7. **人工确认事实**：用户接受、编辑或剔除证据；严重异常进入人工辅助队列。
8. **生成研究简报**：系统只使用已确认的证据生成结构化简报，并保留引用与不确定性说明。

## 7. 信息架构与页面设计

产品采用单项目、五阶段的渐进式工作台。左侧固定导航，主区域显示当前任务。

### 7.1 研究需求

包含主题、地域、时间范围、研究用途、重点问题和补充资料入口。每个研究任务最多补充 5 项材料；文件类型限 PDF、TXT 和 Markdown，单个文件不超过 20 MB，网页链接也计入 5 项额度。公开搜索获得的来源不计入该额度。

### 7.2 研究框架

展示可编辑问题树。用户必须主动确认后才能启动搜索，避免 AI 在错误范围中继续消耗时间和成本。

### 7.3 资料来源

展示来源标题、机构、类型、发布日期、访问状态和 URL。用户可以剔除明显不可信或无关来源。

### 7.4 证据矩阵

这是产品核心页面。默认按研究维度分组，优先展示口径冲突、来源过旧和证据缺失等异常。点击某条记录后展示原文摘录、上下文、来源和 AI 风险提示。用户可将记录标记为已确认、待修改或已剔除。

### 7.5 研究简报

根据已确认的证据生成结构化预览。首版支持复制 Markdown 简报，并将证据矩阵导出为 CSV；不提供 Word 或 PPT 排版。

## 8. 系统模块与边界

低代码编排层连接下列独立模块。每个模块只负责一种任务，并通过结构化数据传递结果。

### 8.1 研究规划器

- 输入：研究任务。
- 输出：研究问题树和搜索计划。
- 依赖：具身智能首版模板。
- 边界：不执行搜索，不生成最终结论。

### 8.2 来源采集与标准化模块

- 输入：搜索计划、用户文件和链接。
- 输出：去重后的来源记录。
- 依赖：公开搜索能力、网页或文件读取能力。
- 边界：不判断研究结论是否正确。

### 8.3 证据提取器

- 输入：来源正文和研究问题。
- 输出：结构化证据记录。
- 依赖：大模型的结构化输出能力。
- 边界：没有直接原文支持时必须返回“证据不足”，不得补写事实。

### 8.4 质量检查器

- 输入：证据记录集合。
- 输出：冲突、时效、口径、完整性和来源风险标签。
- 依赖：确定性规则与 AI 判断。
- 边界：发现冲突但不替用户决定采用哪一个数值。

### 8.5 人工审核队列

- 输入：所有证据记录，异常记录优先。
- 输出：已确认、待修改或已剔除状态。
- 依赖：用户判断；首轮测试允许后台人工辅助。
- 边界：人工修改必须保留修改痕迹，不能伪装成全自动结果。

### 8.6 简报生成器

- 输入：仅限已确认的证据记录。
- 输出：结构化行业研究简报，以及逐句证据映射检查结果。
- 依赖：预设简报结构。
- 边界：不得引入证据记录中不存在的新事实或数字；生成后逐句核对事实性陈述，无法映射到已确认证据的句子必须被阻断或删除。

## 9. 最小数据模型

每条证据记录至少包含以下字段：

| 字段 | 说明 |
|---|---|
| research_question | 证据对应的研究问题 |
| claim | 提取的事实或观点 |
| numeric_value | 可为空的数值字段 |
| unit | 数值单位 |
| geography | 中国、全球或其他明确地域 |
| period | 历史年份或预测期 |
| definition_scope | 来源采用的市场或概念口径 |
| source_title | 来源标题 |
| source_organization | 发布机构或公司 |
| source_type | 官方、公司、研究机构、媒体等 |
| source_url | 可访问链接或用户文件引用 |
| publication_date | 发布日期 |
| evidence_quote | 直接支持结论的原文摘录 |
| risk_flags | 冲突、过期、口径不明、证据不足等标签 |
| review_status | 待审核、已确认、待修改或已剔除 |

## 10. 质量护栏

1. 没有原文证据或来源不可访问的结论，不能标记为已确认，也不能进入最终简报。
2. 市场数据必须同时具备地域、年份或预测期、单位和统计口径；缺少任一关键字段时标记为不完整。
3. 不同口径的数值并列展示，不自动求平均、不强行合并。
4. 公司宣传和新闻转述可以作为线索，但不能自动获得与官方或高质量研究来源相同的可信等级。
5. 简报生成器只能读取审核状态为“已确认”的记录。
6. 所有人工修订和剔除均进入失败案例记录，用于后续评测和迭代。

### 10.1 来源角色

- **一手来源**：政府、监管或标准机构、论文、公司公告和公司官方材料。适合支持政策、技术和特定公司的事实，但公司材料需标记潜在立场偏差。
- **研究来源**：披露研究方法的行业协会、咨询或研究机构。适合支持市场规模、预测和行业结构。
- **二手来源**：具有编辑审核的主流媒体。适合支持事件和观点，关键数字应尽量交叉验证。
- **线索来源**：聚合网站、无引用营销文章和来源不明内容。只能用于发现线索，不能单独支持最终结论。

### 10.2 时效规则

- 融资、商业化、公司进展和竞争格局：发布日期超过 12 个月时标记为“可能过旧”。
- 市场规模、预测和产业链报告：发布日期超过 24 个月时标记为“可能过旧”。
- 技术原理、历史数据和标准文件不按固定时间自动淘汰，但必须展示发布日期。
- “可能过旧”是审核提示，不等同于自动剔除；用户可以在明确原因后确认使用。

## 11. 异常处理

| 异常 | 系统行为 |
|---|---|
| 来源无法访问 | 保存为候选记录并禁止进入简报，提示用户替换或补充来源 |
| 来源内容与标题不匹配 | 标记为引用风险，进入人工审核 |
| 数字或观点冲突 | 并列保留原值、来源和口径，生成冲突提示 |
| 关键字段缺失 | 自动重试一次；仍失败则进入待处理队列 |
| 搜索没有结果 | 明确显示证据缺口，不生成猜测性结论 |
| 文件解析失败 | 标记失败文件，不阻断其他来源处理 |
| 工作流或外部 API 中断 | 保存已完成步骤和记录，允许从失败模块继续 |
| 简报出现证据外事实 | 评测判为严重错误，阻断该版简报交付 |

## 12. 评测与测试方案

### 12.1 离线评测集

建立 30 个具身智能问题，每类 6 个：

1. 市场定义；
2. 市场规模与 CAGR；
3. 技术趋势；
4. 产业链与竞争；
5. 融资与商业化。

每个问题由人工建立参考答案、可接受来源和关键字段要求。每次工作流或提示词调整后使用同一评测集回归。

### 12.2 四层测试

1. **流程测试**：字段缺失、无结果、文件失败、重试和断点续跑。
2. **证据评测**：结论是否被原文支持，引用是否可访问并匹配。
3. **端到端评测**：完成三个标准研究场景，从任务输入运行到证据矩阵和简报。
4. **真实用户测试**：3–5 名目标用户完成任务，记录用时、修改、采纳和复用意愿。

### 12.3 首版验收阈值

| 指标 | 定义 | 目标 |
|---|---|---:|
| 证据支持率 | 结论可以被所附原文直接支持 | ≥85% |
| 引用可访问率 | 来源可打开且指向对应材料 | ≥90% |
| 关键字段完整率 | 数字包含地域、年份、单位和统计口径 | ≥85% |
| 严重事实错误 | 可能误导行业判断的错误 | ≤1/30 |
| 任务时间改善 | 相比用户原有研究流程 | ≥30% |
| 用户价值信号 | 明确认认可用于工作且愿意再次使用 | 至少 3 人 |

小样本结果必须报告原始人数和任务，不包装为精确的留存率或市场结论。

## 13. 真实用户验证与运营

### 13.1 招募

招募 3–5 名精品 FA 实习生或初级分析师。优先选择近期做过行业研究、能够回忆原流程和时间成本的用户。

### 13.2 测试方式

1. 测试前记录用户原有研究步骤、工具、耗时和主要困难。
2. 给所有用户相同的核心任务，并允许补充一个自选问题。
3. 观察用户是否能独立完成框架确认、证据审核和简报生成。
4. 记录人工介入次数、原因和修复方式。
5. 测试后询问可信度、最有价值环节、最大阻碍和复用意愿。

### 13.3 AI 质量运营

将失败案例分为搜索、解析、证据、口径、引用、生成和交互七类。优先修复高频且影响最终判断的问题；界面美化和低频便利功能排在其后。

## 14. 2–3 周实施边界

| 阶段 | 建议时间 | 交付物 |
|---|---:|---|
| 用户与问题验证 | 2 天 | 访谈记录、旧流程图、痛点优先级 |
| 产品与评测设计 | 2 天 | 规格、原型、30 题评测集和人工基准 |
| 核心工作流搭建 | 4–5 天 | 规划、采集、提取、质检和简报流程 |
| 交互产品搭建 | 2–3 天 | 五阶段轻量工作台 |
| 内部测试与修复 | 2 天 | 错误分类和首轮迭代 |
| 真实用户测试 | 2–3 天 | 3–5 名用户测试记录 |
| 作品集整理 | 2 天 | 案例复盘、演示素材和简历描述 |

若进度受阻，功能取舍顺序如下：先保住证据矩阵、来源追溯、人工审核和基础评测；再保住结构化简报；最后才考虑导出形式和视觉细节。

## 15. 作品集与简历输出

最终案例必须包含以下证据：

1. 问题发现：访谈记录、旧流程和痛点优先级。
2. 产品设计：目标用户、JTBD、范围取舍、流程和原型。
3. AI 设计：模块边界、结构化证据、人工审核和质量护栏。
4. 评测能力：评测集、指标、错误分类和迭代前后对比。
5. 运营能力：用户招募、测试行为、反馈和下一轮计划。
6. 结果表达：真实人数、真实任务和真实改善，不使用未经验证的效果数字。

## 16. MVP 完成定义

只有同时满足以下条件，首版才视为完成：

1. 用户可以从研究任务输入走到证据矩阵和研究简报。
2. 所有进入简报的事实均来自已确认证据记录。
3. 四类关键异常——来源不可访问、数字冲突、字段缺失、流程中断——均有可观察的处理结果。
4. 30 题离线评测和三个端到端场景均已执行并保留结果。
5. 至少 3 名目标用户完成测试，且访谈和行为记录可供复盘。
6. 作品集如实呈现未达标指标、人工介入和产品局限。

## 17. 已确认的关键决策

- 求职作品集为主，真实用户验证为辅；当前不以创业付费验证为目标。
- 第一目标用户是精品 FA 实习生和初级分析师。
- 核心任务是具身智能行业研究，不包含项目 sourcing。
- 输出是证据矩阵加结构化行业研究简报。
- 资料来源是公开网络搜索加每个任务最多 5 项用户文件或链接。
- 中国商业化、融资和产业链为主，全球技术与标杆公司作为对照。
- 采用低代码工作流产品，允许人工质检兜底。
- 产品周期为 2–3 周，投入接近全职。
